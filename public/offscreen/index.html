OffscreenCanvas & reprojecting parts of the DOM

<canvas-slot worker="./renderer.js"> hands its canvas to a worker. On each paint the main thread captures the slotted elements with captureElementImage() and transfers the ElementImage snapshots. The worker animates them with its own requestAnimationFrame.

Takeaways

  • Worker rendering works with the transferred canvas: captureElementImage() → postMessage(…, [img]) → drawElementImage(img) on the OffscreenCanvas, and a snapshot can be redrawn every frame until it's replaced or closed.
  • Snapshots are tied to their canvas. A new OffscreenCanvas(), or any canvas other than the source (or its transferred OffscreenCanvas), throws "The source was captured from a different canvas". To show DOM in a second canvas you copy pixels (drawImage(sourceCanvas)), which loses interactivity.
  • The worker can't make new snapshots. Only the main thread's rendering update produces them, so a blocked main thread means motion continues but content freezes.
  • Hit testing follows the worker. Worker-side draws update geometry asynchronously and fire elementgeometryupdate on the canvas element.
  • The source canvas must render. display: none and visibility: hidden canvases never record a snapshot ("No cached paint record"), and a canvas positioned far off-screen is culled (transparent). A visible-but-opacity: 0 canvas does work, which is a usable "hidden source" trick.
