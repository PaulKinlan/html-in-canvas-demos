Sound driving DOM in a canvas

The card below is HTML drawn through a fragment shader. Press play on its <audio> controls. An AnalyserNode writes the level of four frequency bands to four CSS custom properties. The shader reads them as uniforms and the bars read them with CSS. The text field and the buttons keep working.

  1. The markup. An ordinary card with an <audio controls> element. fx names the effect.
  2. Sound to four numbers. The audio element is routed through an AnalyserNode. Each frame, four bands of its spectrum are written to custom properties.
  3. Picture and sound in step. The levels are held back by the output latency the context reports.
  4. The CSS. The bars use the four properties directly.
  5. The effect. The same four properties arrive in the shader as u_amount, u_xy and u_progress.
  6. Inside the library: the upload and the draw.

How it works

  • The fx library registers --fx-amount, --fx-x, --fx-y and --fx-progress as numbers and passes them to every effect. This page uses them as four band levels from 0 to 1.
  • The page never calls a canvas API. It sets four style properties per frame.
  • An AudioContext stays suspended until the person taps, so the analysis starts on the first play event.

Findings

From Chromium 157 with software rendering. The rows above say what your browser does.

  • Works: <audio controls> in a canvas. The native audio controls are drawn, and play, seek and volume work under the shader because the element keeps its layout position for hit testing.
  • Works: custom properties as the link. One set of four numbers drives CSS inside the element and the shader that draws the element. Nothing else connects the audio code to the drawing code.
  • Works: analysis with no gesture, off line. OfflineAudioContext decodes and analyses the clip without a tap, which is how the second live check gets band levels. Live analysis needs the tap.
  • Cost: one upload per frame. The bars change the DOM every frame, so the element is uploaded to the texture every frame while sound plays. With the bars removed, only the uniforms change and the texture is reused.
  • Built, not heard: the delay. The picture is held back by AudioContext.playbackStats.averageLatency where the browser has it, else outputLatency. The test browser has no sound card and reports 0, so whether picture and sound line up on a phone or on Bluetooth headphones is for a person to judge. The checkbox turns the delay off for comparison.
  • Not verified here: audible output and timing on a real device (the test browser has no sound card), the microphone, and the WebGPU route on screen.
