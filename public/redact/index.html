  3. Bar. A filled rectangle over each line of each range.
  4. Pixels. The canvas copied into large cells.
  5. Blur. The element drawn again through ctx.filter and a clip.
  6. Changing letters.
  7. Copy. Replace redacted characters in the clipboard text.
  8. Remove the text from the DOM.

How it works

“Redact selection” stores the selection as two character offsets and adds a Range for it to a CSS Custom Highlight with no ::highlight() rule. The element reads the rectangles of that Highlight's ranges and the effect draws over them after it has drawn the text. The drawing is only pixels. The characters stay in the DOM, so anything that reads the DOM still gets them: copy, textContent, find-in-page, a screen reader. “Remove the text from the DOM” replaces each redacted character with a block character, after which the canvas bar covers blocks.

Live checks

These start when you press the button. They use their own fixture.

Findings

Measured in headless Chromium 157 on Linux with a software renderer, 2026-11-21.

  • A bar drawn after the element covers every pixel of the range in the canvas and in a PNG made from it (checked below, pixel by pixel).
  • The canvas hides nothing from the DOM. After a redaction, textContent, Range.toString() and copy return the covered text. A canvas redaction is only safe as an exported picture, or together with removing the text.
  • Pixels and blur are made from the text's own pixels, so they keep some information about it: length, word gaps and rough letter shapes. The bar keeps only the length. Changing letters keeps the length and the font.
  • ctx.filter applies to drawElementImage(). The blur style is the element drawn a second time through a blur() filter and a clip.
  • A canvas can be the source of its own drawImage() after drawElementImage(). The pixel style reads the part of the canvas it is about to replace. The canvas is not tainted by same-origin element content, so PNG export works. The page reads pixels only from a drawImage() copy of the canvas.
  • Replacing characters in the DOM changes line breaks when the block character is wider than the letters it replaces. The offsets stay valid because the number of characters does not change.

Not verified: what find-in-page and TalkBack report for a redacted range (both read the DOM, so the expected answer is the original text until it is removed), and selecting by touch on a phone.
