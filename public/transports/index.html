What the failures point to

  • An ElementImage is not an image. It is not a CanvasImageSource: drawImage, createImageBitmap and VideoFrame all reject it, and it only draws into its own canvas (2D or WebGL, main thread or worker). Every route out goes through that canvas first.
  • Fastest way out: a worker that owns the canvas. Snapshot → worker → drawElementImage → transferToImageBitmap() gives a GPU-backed bitmap per frame with no main-thread rasterization, and from there it can go to any canvas, tab or origin.
  • Ways to stay DOM instead of pixels: nest canvases (an inner drawable canvas is itself a drawable element of the outer one), put a same-origin iframe inside the canvas (a whole document reprojected live), or use one page-wide overlay canvas with pointer-events: none so any element can be drawn anywhere while the page stays clickable.
  • Across origins, send bitmaps or bytes. VideoFrame and streams of them fail to deserialize in a cross-origin document (a silent messageerror), and MediaStreamTrack does not transfer at all. ImageBitmap, a ReadableStream of ImageBitmaps, Blobs, ArrayBuffers, encoded video chunks and WebRTC all get through.
  • Hit testing stops at the canvas edge. updateElementGeometry accepts a transform outside the canvas box, but the element is not hit-testable there. Interactivity at a remote mirror means forwarding input (as in the cross-tab demo) or making the canvas bigger (the overlay).
  • Not testable in every environment: WebGPU needs a GPU adapter, and SharedArrayBuffer needs cross-origin isolation headers, which this site does not send yet.
