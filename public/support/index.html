Show the code sharing one panel, not the screen
  1. The app is ordinary markup. data-shareable marks what may be picked, data-private marks fields that must never leave.
  2. Turn the picked element into a surface with one call. el is the panel the user clicked. Input from the other side is refused unless the user ticked the box.
  3. Show the user exactly what leaves the page. surface.mirror is the redacted copy, an ordinary canvas.
  4. For a model: a JPEG of the copy and a list of its elements.
  5. For a person: share the surface in a room and give them the link.
  6. The agent's page.
  7. Inside attachSurface(): the element gets a shadow root with a drawable canvas and a slot, so its children are drawn without being moved.
  8. Inside: the shareable copy, with private fields blacked out.
  9. Inside: replaying approved input on the real elements.
  10. The whole library.

How it works

  1. Pick. Clicking a panel gives that element a shadow root containing a canvas and a slot. Its children stay where they are in the document and are painted through the canvas, which is what makes their pixels available. Nothing is cloned or re-rendered.
  2. Redact. Each frame is copied to a second canvas, where anything marked data-private (and every password field) is covered. Only that copy leaves the page. The same rule withholds their values from the element list.
  3. Send pixels and meaning. A person gets live video over WebRTC. A model gets a JPEG. Both also get a list of the region's controls, read from the real DOM: role, name, value. That list is what lets either of them say "the Retry payment button" and have it mean something.
  4. Act with permission. The agent's pointer is drawn on the canvas for you to see. Clicks and typing from the agent are refused until you allow them. The model can only propose a click or a value; you press the button that makes it happen.

Takeaways

  • Element sharing is a different permission model from screen sharing. The page chooses what can be shared, the user chooses which part, and nothing else is ever in the frame: no other tabs, no notifications, no address bar.
  • The page can redact, because it knows its own DOM. A screen recorder sees pixels. This sees elements, so "never send the card number" is a selector.
  • A model does better with the DOM beside the picture. The picture shows layout and state; the element list gives exact labels and values and gives the model something to point at and act on.
  • Any element with a shadow root to spare can be converted in place. Grid and flex containers need their layout properties copied to the inner box. Elements that already have a shadow root, or cannot have one, need a wrapper instead.
  • The sharing tab must stay visible. It is the page's own paint that is being sent, so a hidden tab sends nothing.
