Slotting DOM into a canvas

HTML-in-canvas wants the drawn DOM to be a descendant of the <canvas>. A shadow root lets the canvas live in the shadow tree while your content stays in the light DOM: each named <slot> inside the canvas pulls in the matching child, and that child is drawn with drawElementImage(). The text below is real DOM: select it, tab to the input, type, click.

Re-slotting: move content in and out of the canvas

An element is drawn by the canvas when two things are true: it is a child of <canvas-slot>, and it has a slot="…" name. Make both true to move it in. Undo them to move it out. It is the same element the whole time, so what you typed into it and its event listeners come along. 

// Move in
card.setAttribute('slot', 'current');
stage.append(card);              // stage is the <canvas-slot>

// Move out
card.removeAttribute('slot');
shelf.append(card);              // anywhere outside the <canvas-slot>

// Draw whatever is in the slot. This runs again by itself after every change.
stage.onrender = ({ draw }) => draw('current', 12, 12);

Try it. Tap a card to move it into the canvas, and tap it in the canvas to send it back. Type in the Kiwi input before and after.

The complete page for this demo (paste it into a blank .html file)

If the element is already a child of <canvas-slot>, changing only its slot attribute is enough: an element with no slot name is not drawn and not shown, and one with a name is. If you draw the same element more than once, draw the copy people should interact with last, because the last draw decides where taps land.

Content that lives outside the element

Short answer: yes, content written anywhere on the page can be drawn in the canvas, but something has to bring it in. The browser rule is that a <slot> only takes children of the element that owns the shadow root, and HTML-in-canvas only draws elements that are laid out inside the canvas. So an element elsewhere on the page is out of reach until it becomes a child of that element, or until that element is made big enough to already contain it. These are all the routes, with the ones that fail included. Each is checked live in the table further down.

  1. Just give it a slot name ✗ does nothing

    The markup you would hope works. The slot is in <canvas-slot>'s shadow root, and the footer's child is not a child of <canvas-slot>, so it is never assigned. It stays where it is as ordinary HTML.

    <canvas-slot id="stage"></canvas-slot>
<footer>
  <aside slot="promo">…</aside>      <!-- not a child of canvas-slot: ignored -->
</footer>

  2. Move it in yourself ✓ works

    Two lines. The element is moved, not copied. This is what the re-slotting demo above does.

    const stage = document.getElementById('stage');
const promo = document.querySelector('footer aside');

promo.setAttribute('slot', 'promo');
stage.append(promo);                          // in

promo.removeAttribute('slot');
document.querySelector('footer').append(promo);   // and back out

  3. Point <canvas-slot> at it: from="…" ✓ works

    New in canvas-slot.js. from is a CSS selector; whatever matches is brought in when the page loads, and its slot name is its slot attribute or else its id. In script, stage.adopt(element) does the same for one element and stage.release(element) puts it back exactly where it was (a comment node marks the spot). Under the hood this is route 2: there is no way to draw it without moving it. It uses moveBefore() where the browser has it, so focus and running animations survive the move. 

    <canvas-slot id="stage" from="#promo"></canvas-slot>
<footer>
  <aside id="promo">…</aside>
</footer>

<script type="module">
  const stage = document.getElementById('stage');
  stage.onrender = ({ draw }) => draw('promo', 16, 16);

  stage.release(document.getElementById('promo'));   // back to the footer
  stage.adopt('#promo');                             // in again
</script>

    The catch with routes 2 and 3: the element has a new parent while it is in the canvas, so CSS that reached it through its old ancestors (footer > aside) stops matching. Style it by class or id.

  4. Make the host bigger: a shadow root on <body> ✓ works

    If the shadow root is on <body>, every top-level element of the page is a child of the host. Any of them can opt in with only slot="stage", and nothing is moved. Everything else flows through a default <slot> as before. The limit: only direct children of <body> can opt in. See it running. 

    <body>
  <p>Normal content.</p>
  <aside slot="stage" drawable>I opted in.</aside>
  <p>More normal content.</p>

  <script type="module">
    const root = document.body.attachShadow({ mode: 'open' });
    root.innerHTML = `
      <canvas content="drawable" layoutsubtree style="display:block;width:100%;height:130px">
        <slot name="stage"></slot>
      </canvas>
      <slot></slot>`;                    // everything else, in its normal place
    const canvas = root.querySelector('canvas');
    const ctx = canvas.getContext('2d');
    canvas.onpaint = () => {
      ctx.reset();
      let x = 20;
      for (const el of root.querySelector('slot[name=stage]').assignedElements()) {
        ctx.drawElementImage(el, x, 20, el.offsetWidth, el.offsetHeight);
        x += el.offsetWidth + 20;
      }
    };
  </script>
</body>

  5. Plain <canvas><slot> plus one script: light-slots.js ✓ works

    No custom element. You write a <slot> inside a normal <canvas>, and the script puts a shadow root on the canvas's parent so that the canvas's siblings can be slotted. Add slots="document" to the canvas and matching elements anywhere in the page are moved next to it first. See it running, and see how it works, step by step, in pictures. 

    <script type="module" src="/lib/light-slots.js"></script>

<canvas id="stage" content="drawable" layoutsubtree slots="document">
  <slot name="promo"></slot>
</canvas>
<footer>
  <aside slot="promo">…</aside>
</footer>

  6. No component at all: a <slot> as a mount point ✓ works

    The pattern from Extensible Web Apps: a <slot name="…"> in the light DOM is not a real slot, it is a named place that script appends things to. Put one inside a plain <canvas> and it works as a mount point with no custom element and no shadow root. A comment node remembers where the element came from. See it running. 

    <canvas id="stage" content="drawable" layoutsubtree>
  <slot name="main"></slot>
</canvas>
<aside id="card" drawable>…</aside>

<script type="module">
  const canvas = document.getElementById('stage');
  const ctx = canvas.getContext('2d');
  const slot = canvas.querySelector('slot[name="main"]');
  const card = document.getElementById('card');
  const mark = document.createComment('card was here');

  // In: leave a marker, move the card into the slot.
  card.before(mark);
  slot.moveBefore(card, null);          // keeps focus and state; append() also works
  canvas.requestPaint();

  // Out: back to the marker.
  // mark.parentNode.moveBefore(card, mark); mark.remove(); canvas.requestPaint();

  canvas.onpaint = () => {
    ctx.reset();
    for (const el of slot.children)
      ctx.drawElementImage(el, 16, 16, el.offsetWidth, el.offsetHeight);
  };
</script>

  7. Assign it by hand with slot.assign() ✗ does nothing

    Manual slot assignment sounds like the escape hatch, but it has the same rule: assign() silently ignores any node that is not a child of the host.

    const root = host.attachShadow({ mode: 'open', slotAssignment: 'manual' });
root.innerHTML = '<canvas content="drawable" layoutsubtree><slot></slot></canvas>';
const slot = root.querySelector('slot');

slot.assign(document.querySelector('footer aside'));
slot.assignedElements();   // [] : it is not a child of host

  8. Leave it where it is and draw it twice: <dom-portal> ✓ works, differently

    A different idea for a different need. <dom-portal for="promo"> shows a second live picture of an element somewhere else on the page. It does not bring the element into your canvas: it wraps the element where it sits and stretches one canvas over both places. Use it when you want a mirror, not when you want to draw the element yourself. See /portal/. 

    <script type="module" src="/lib/dom-portal.js"></script>

<aside id="promo">…</aside>
…
<dom-portal for="promo" scale="0.5"></dom-portal>

What would remove the need for any of this: letting a <canvas content="drawable"> treat its own <slot> children as real slots for elements in the same document, or giving slots a way to reference an element by id. Neither exists today.

A drawable wrapper around the slot

<canvas-slot> asks you to name each child with slot="…" and draws them one by one. The other pattern leaves the author's markup completely alone: inside the canvas there is one real element marked drawable that wraps a default <slot>. Everything the author wrote lands in that wrapper and is drawn as a single image with one call. The children stay live, so the button below still works. 

<canvas content="drawable" layoutsubtree>   <!-- in the shadow root -->
  <div drawable id="wrapper">
    <slot></slot>                           <!-- all the author's children -->
  </div>
</canvas>

ctx.drawElementImage(wrapper, 0, 0, wrapper.offsetWidth, wrapper.offsetHeight);

Findings

Every point links to where it is shown working, or failing, on this page.

  • Slotted light-DOM elements can be drawn directly. drawElementImage(lightChild) works when the light child is assigned to a slot inside the canvas, because layout and paint use the flat tree. Shown in the first demo and in the first row of the live table.
  • The <slot> itself can't be the drawable. It is display: contents, so it has no box and no paint record ("No cached paint record for element"). Put drawable on the slotted element, or on a real wrapper element in the shadow tree around the slot. It fails live in the table ("Mark the <slot> itself drawable").
  • A shadow wrapper works too. <div drawable><slot></slot></div> inside the canvas draws everything slotted into it as one image, which is handy when you don't want to touch the author's markup. Working demo and full code.
  • The limit is the host's children. A slot can only reproject children of its shadow host, so an element elsewhere in the page has to be moved in, or the host made bigger. All the routes, with code.
  • Moving in and out is two lines each way. Set slot and append to move in; remove slot and append elsewhere to move out. Demo and full code.
  • Always pass a size to drawElementImage(). Without one the element is drawn in canvas pixels. On a canvas sized for a high-density screen with ctx.scale(dpr, dpr), that makes it dpr times too big, and its hit-testing box grows with it. <canvas-slot>'s draw() helper passes the size for you. It fails live in the table ("On a sharp canvas…"), which reports the size it got.
  • Hit testing, focus and selection follow the drawn position, because drawElementImage updates the element's geometry automatically. Every demo on this page relies on it: the buttons and inputs work where they are drawn. Checked live ("Hit testing lands…").
