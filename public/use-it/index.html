Use it: the smallest working markup for nine drop-in elements

Nine elements from this site's libraries that work on another page with one script tag and a few lines of markup. Each box below runs the markup shown under it. Every one here draws with a 2D canvas, so the page opens no WebGL context. The shader attribute fx has its own block on /shader-css/.

The libraries are served with Access-Control-Allow-Origin: *. They need Chrome with the HTML-in-canvas API. Without it each element leaves its children as plain HTML.

<effect-frame><selection-fx><glyph-field><select picker><canvas-slot><dom-portal><dom-lens><input list picker><input type="time" picker>

How it works

The markup in each box is in this page's own source, between two comments. The listing under the box is the same text with the script tag of the library put before it. A live check compares the two. This page loads each library when its section comes near the screen, so on your own page the element starts sooner than it does here.

Findings

Measured in headless Chromium 157 on 2026-11-22. Not yet run on a phone.

  • Nine elements start from one script tag and the markup shown: each was upgraded or taken over by its library, and the nine listings match the markup that runs.
  • By touch at 412 px: typing in the field inside <effect-frame> worked, a double click selected a word in <selection-fx>, the link in <glyph-field> was found by a hit test, a tap opened the wheel of the select and the clock of the time input, a tap unticked the checkbox on the turned card of <canvas-slot>, typing in the copy made by <dom-portal> changed the one input, and typing a letter opened the datalist's pills.
  • Writing this page found a fault in select-picker.js: an option marked selected in the markup was lost when the library moved the options into its canvas, and the last option became the value (09:05 where the markup says 06:45). The library now keeps selectedIndex across the move.
  • The page opens no WebGL context: every element here draws on a 2D canvas, <dom-lens> because of pipeline="2d".
  • Not verified: Chrome 159 on Android, and the snippets on a page of another origin. The libraries were loaded from this origin in every test.
