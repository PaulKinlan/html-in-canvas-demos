Start here

HTML-in-canvas lets a <canvas> draw real elements: a form, a paragraph, a whole component. They are drawn as pixels you can rotate, bend, shade or send somewhere else, and they are still the elements. You can click them, type in them, select their text and reach them with a screen reader. This page is the whole idea in one small example.

Turn it on

The API is experimental and only in Chromium browsers. In Chrome 148 or later, on desktop or Android, open chrome://flags/#canvas-draw-element, choose Enabled and restart the browser. A site can also switch it on for its visitors with the html-in-canvas origin trial. The demos here are tested in Chromium 157 on desktop and Chrome 159 on Android.

Check for it before you rely on it, and leave the plain HTML in place when it is missing:

const supported = 'drawElementImage' in CanvasRenderingContext2D.prototype;

The names have changed between builds. Current ones are used throughout this site: the canvas attribute content="drawable" (older builds called it layoutsubtree, so the demos write both), the drawable attribute on each element to draw, and the WebGL and WebGPU calls texElementSubImage2D() and drawElementImageToTexture(). The explainer is the source of truth.

The four moves

  1. Opt the canvas in, and put the element inside it

    The canvas gets content="drawable". Its children are then laid out and kept in the accessibility tree, but not shown: showing them is now your job. Each element you will draw gets the drawable attribute. 

    <canvas id="canvas" content="drawable" layoutsubtree>
  <form id="card" drawable> … </form>
</canvas>

  2. Give the canvas as many pixels as it covers

    A canvas has a size in CSS and a separate size in pixels. On a phone one CSS pixel is two or three real ones, so match them or the text is soft. devicePixelContentBoxSize gives the exact number. 

    new ResizeObserver(([entry]) => {
  const box = entry.devicePixelContentBoxSize[0];
  if (canvas.width !== box.inlineSize) canvas.width = box.inlineSize;
  if (canvas.height !== box.blockSize) canvas.height = box.blockSize;
  canvas.requestPaint();
}).observe(canvas, { box: 'device-pixel-content-box' });

  3. Draw in the paint event

    The browser fires paint on the canvas whenever a drawable child changes how it looks: a key typed, a hover style, a focus ring, new text. You do not poll. canvas.requestPaint() asks for one yourself, for an animation or after a resize. 

    canvas.onpaint = () => {
  const dpr = canvas.width / canvas.clientWidth;
  ctx.reset();
  ctx.scale(dpr, dpr);          // draw in CSS pixels from here on
  ctx.translate(24, 30);
  ctx.rotate(-0.04);
  // …
};

  4. Call drawElementImage()

    It draws the element like drawImage() draws a picture, under whatever transform, clip, shadow or filter the context has. It also moves the element's hit box to where you drew it, which is why clicks land on what you see. Always pass the width and height. 

    ctx.drawElementImage(card, 0, 0, card.offsetWidth, card.offsetHeight);

What you get, and what you don't

Kept, with no code from you

  • Clicks, hover, focus and typing at the drawn position (2D drawing)
  • Tab order, text selection, find-in-page
  • The accessibility tree: a screen reader sees the elements, not a picture
  • CSS, animations, form state, scrolling inside the element
  • Sharp text at any scale, because the element is painted again, not stretched
  • Reading the pixels back: the canvas is not tainted

Yours to handle

  • The element has to be a descendant of the canvas (slots get round that)
  • An element you do not draw is invisible but still focusable (accessibility audit)
  • With WebGL or WebGPU nothing moves the hit box for you (Shader CSS)
  • One element has one hit box, however many times you draw it (dom-portal)
  • Cross-origin iframes inside the canvas draw blank (Across origins)
  • A fallback for every other browser: keep the markup useful as plain HTML

Beyond 2D

Three more calls cover everything else on this site. Each has a page that shows it working.

  1. An element as a GPU texture

    In WebGL, texElementSubImage2D() uploads the element into a texture you have allocated at its size. In WebGPU it is queue.drawElementImageToTexture(). From there it is any shader or any 3D surface. See Shader CSS and a form in a three.js scene. 

    gl.bindTexture(gl.TEXTURE_2D, texture);
gl.texElementSubImage2D(gl.TEXTURE_2D, 0, 0, 0, card);        // WebGL: level, x, y, element

device.queue.drawElementImageToTexture({ source: card }, { texture });   // WebGPU

  2. Telling the browser where the element is

    A shader can put the element anywhere, so the browser cannot know where clicks should go. You say so with updateElementGeometry() and a matrix. The same call lets one element answer in two places, or follow a mesh. See dom-portal and Physical UI. 

    canvas.updateElementGeometry(card, {
  canvasTransform: new DOMMatrix().translate(x, y).rotate(angle),
});

  3. A snapshot you can hand to a worker

    captureElementImage() returns an ElementImage: one frame of the element, transferable with postMessage(). A worker that owns the canvas (through transferControlToOffscreen()) can draw it for as many frames as it likes. A snapshot only draws into the canvas it came from. See OffscreenCanvas. 

    const image = canvas.captureElementImage(card);
worker.postMessage({ image }, [image]);
// in the worker: ctx.drawElementImage(image, x, y, width, height)

Where it bites

The mistakes everyone makes once, and the page that shows each one.

What you seeWhyWhat to do
"Descendants passed to DrawElementImage must have the 'drawable' attribute"The element is missing drawable, or it is not inside this canvas.Add the attribute. For content that lives elsewhere, use a slot: Just a slot in a canvas.
"No cached paint record for element"The browser has not painted the element yet: the first paint came early, the canvas is far off screen, or it is display: none or visibility: hidden.Catch it and call requestPaint() again a frame later. Hide a source canvas with opacity: 0, not visibility.
The element is drawn two or three times too big on a phoneWithout a width and height, drawElementImage(el, x, y) draws in device pixels.Always pass el.offsetWidth, el.offsetHeight. Desktop emulation hides this one: test on a real phone.
Soft, blurry textThe canvas has fewer pixels than it covers on screen.Size it from devicePixelContentBoxSize (move 2 above).
The canvas goes blank when you resize itAssigning canvas.width or height clears it, even to the same value.Assign only when the number changed, then requestPaint().
A child is narrower than you expectedChildren of a drawable canvas shrink to fit their content.Give the element a width.
A <slot> inside the canvas does nothingSlots only project inside a shadow tree.Put the canvas in a shadow root; declarative shadow DOM needs no script. Just a slot in a canvas, plain HTML.
Clicks land where the element used to be (WebGL, WebGPU)Only 2D drawElementImage() moves the hit box.Call updateElementGeometry() each frame. Shader CSS.
Two copies drawn, only one takes clicksOne element, one hit box. The last draw wins.Draw the copy that should be interactive last, or move the hit box under the pointer. dom-portal.
Tab reaches a control nobody can seeAn element in the canvas that you do not draw is still focusable.Draw it, or mark it inert or hidden. Accessibility audit.
"The source was captured from a different canvas"An ElementImage only draws into its own canvas, or that canvas transferred to a worker.To show DOM in another document, send pixels (ImageBitmap, video) and send input back. Across tabs, Transport lab.
A cross-origin iframe in the canvas is blankThe browser never paints content the page is not allowed to read, so the canvas stays readable.Have the other origin send its own pictures. Embeddable live cards, slot-view.

A learning path

Nine pages, each adding one idea to the ones before. After that, follow your interest: every demo says what it teaches and what to read first.

    Glossary

    The words this site uses, with one meaning each.

    Drawable canvas
    A <canvas content="drawable">. Its children are laid out and stay in the document, and the canvas decides how they appear.
    Drawable element
    A descendant of a drawable canvas with the drawable attribute. Only these can be passed to drawElementImage().
    paint event
    Fired on the canvas when a drawable element needs drawing again, or after requestPaint(). event.changedElements lists which ones changed.
    Paint record
    The browser's stored drawing instructions for an element. drawElementImage() replays them, which is why zoomed text is sharp. No record yet means nothing to draw.
    Hit box (element geometry)
    Where the browser believes an element is, for clicks, hover, focus rings and the caret. 2D drawing sets it. updateElementGeometry() sets it by hand.
    ElementImage
    A snapshot of one element at one moment, from captureElementImage(). Transferable to a worker or another window, but it only draws into the canvas it came from.
    Light DOM, shadow root, slot
    The light DOM is the markup you write. A shadow root is a hidden subtree attached to an element. A <slot> in the shadow root displays light-DOM children there without moving them. Put the canvas in the shadow root and your markup can stay outside it.
    Reprojection
    Showing an element somewhere it is not: a second place on the page, a worker's canvas, another tab, another origin, a 3D surface.
    Input forwarding
    When the picture of an element is shown in another document, pointer and key events there are sent back and replayed on the real element.
    Read-back-allowed rendering
    The rule that keeps the canvas readable: anything the page could not otherwise see, such as a cross-origin iframe or visited-link colours, is left out of the drawing.
    Live checks
    The pass and fail tables on each demo. They run in your browser, so what the page claims is what your browser does. A row marked "fails as expected" is a limit of the API, not a bug.
