  2. 2D route: 5-argument drawElementImage() in CSS pixel units. Backing dimensions track device-pixel-content-box and only reassign when changed.

How it works

Every workload renders 16 sibling cards in a 4 by 4 grid. On the plain DOM route the grid sits directly in the stage. On the 2D and WebGL routes the grid sits inside a single <canvas content="drawable" layoutsubtree>, and each of the 16 cards carries its own drawable attribute. On every animation frame during a timed run, the script mutates only 1 of the 16 cards (cycling through cards 0 to 15) without forcing requestPaint(), so Chromium decides which siblings need fresh paint records.

The 2D handler draws all 16 cards with 5-argument drawElementImage(card, x, y, w, h) after scaling the context to device pixels. The WebGL handler opens one context via ElementGL from /lib/element-gl.js, reads e.changedElements on each paint event, re-uploads only the listed cards with gl.texElementSubImage2D(), draws all 16 quads, and calls canvas.updateElementGeometry() whenever a card box changes.

Each timed run warms up for 4 frames, resets counters, then measures for about 600 ms (at least 14 frames). A PerformanceObserver watches long-animation-frame entries over the same window and splits every frame over 50 ms into script time (renderStart to styleAndLayoutStart), style and layout time (styleAndLayoutStart to end of main-thread work), and post-main-thread raster and presentation time (end of frame to presentationTime). When a full sweep finishes, the page sends a compact summary to window.__gfx.report('perf-subtree', ...) and formats a Markdown table you can copy.

Findings

  • Not verified on real hardware yet. This page was built on 2026-11-26 and hasn't been timed on a real phone or desktop GPU yet. Press "Run full matrix" on Chrome with #canvas-draw-element enabled, then copy the Markdown table or inspect npm run reports to record measured numbers.
  • Why 16 separate drawable siblings matter. Putting drawable on each card lets the WebGL path skip texElementSubImage2D() for the 15 unchanged cards when e.changedElements names only the mutated sibling. Any over-invalidation shows up as changedElements > 1 and immediately multiplies texture uploads.
  • Containment requires definite card sizes for contain: strict. The 4 by 4 grid fixes each track at 78 px tall so contain: none, contain: layout paint and contain: strict keep the same card geometry while isolating internal layout and paint bleed.
  • Long Animation Frames only appear above 50 ms. Fast workloads on a desktop GPU will report 0 (<50 ms) LoAF entries; on a phone or under heavy blur, shadow and SVG filter stacks, post-main-thread presentation stalls show up in the third column of the LoAF split.
