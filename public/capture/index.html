Element capture: any element to PNG, video or print

One call turns an element that was never written for canvas into pixels: captureElement(el), recordElement(el), printElement(el), and capturePage() for a whole ordinary page. Under the hood a temporary HTML-in-canvas canvas takes the element's place for one frame. The tests below say what survives that and what does not.

What this shows

  • Yes, body can be wrapped in a canvas for one frame. The snapshot is ready in the first rendering update after the canvas goes in: the paint event fires in that same frame, so there is no waiting and nothing to await but one frame.
  • The shadow-root route moves nothing. A shadow root on <body> holding canvas > div[drawable] > slot reprojects every body child without touching the light DOM: no mutation records for the page, selectors like body > main keep matching, focus, caret, iframes and scroll position stay put. Its cost is permanent: a shadow root cannot be removed, so body keeps a bare <slot> afterwards and the page can never attach its own.
  • The move route needs moveBefore(). With it, moving body's children into a canvas and back keeps focus, caret, form state and iframes alive. With plain append the iframes reload and focus is lost, and taking an iframe out of a canvas in the frame it was drawn crashed the tab.
  • CSS animations restart when an element becomes a canvas descendant, on every route. The library reads currentTime before and seeks the restarted animations back.
  • Fixed and sticky need a stand-in viewport. A drawable element is a containing block, so fixed elements attach to it. Wrapping the content in a viewport-sized frame with an inner scroller set to the page's scroll offset gives a faithful viewport shot. In a full-page shot fixed elements land at the end of the document and sticky ones at their static position.
  • Cross-origin iframes come out blank, by design, and so do cross-origin images without CORS. Same-origin iframes paint.
  • Output is re-rasterized, not upscaled. drawElementImage(el, 0, 0, w × 4, h × 4) replays the element's paint record at the new size, so a 4× PNG has sharp text and hairlines. That is what makes print output usable.
