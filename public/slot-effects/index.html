Shader slots: point the attribute at a fragment shader

effect also takes #id of a <script> or url(file.frag). The shader is one function: p is in CSS pixels from the slot's top-left and tex(p) samples the slot. CSS filters you can write yourself. Edit the one on the left.

One registry, two ways in

<canvas-slot effect> and the fx attribute share one list of effects, one shader contract and the same CSS properties. Use fx to shade one element where it already sits in your layout; use <canvas-slot> when several pieces share a canvas and you want to place them. An effect defined once works in both.

WebGPU backend

Every effect slot on this page uses WebGPU by itself when the page has a usable device (a real adapter that passes a self-test) and each of its effects has WGSL source; the switch under the first demo names a route by hand and says why WebGPU is not in use. backend="webgpu", as below, asks for it outright. It draws each slot with queue.drawElementImageToTexture() and a WGSL version of the effect (fn fx(p: vec2f) -> vec4f). Built-in WGSL: tilt, ripple, dissolve, glass, haze, crt, page-curl. If WebGPU cannot start, rejects the first frame or loses the device, the element falls back to WebGL by itself.

How it works

  • Same element, same markup. <canvas-slot> without effect behaves exactly as before (2D context, onrender). With it, the canvas gets a WebGPU or WebGL2 context instead and the shader code is loaded on demand.
  • Each slot is a texture. texElementSubImage2D() uploads a slot only when the browser says it repainted. One full-canvas quad per slot runs the effect's fragment shader and is blended over the last.
  • No render loop to write. Slots stack as they do without an effect; set onrender only if you want to place them. The element repaints itself while an effect is moving and sleeps when nothing changes.
  • CSS is the control surface. The four --fx-* properties are read from each slotted element every frame while it is on screen. A paint happens only when one changed.
  • Hit testing follows tilt. An effect can say where it moves the element (geometry, a DOMMatrix). The shader gets the inverse to sample with, and updateElementGeometry() gets the matrix so clicks, focus rings and selection land on the tilted card. Displacement effects (ripple, curl) are visual only, like a CSS filter.
  • A canvas keeps its first context type. Adding or removing effect later swaps in a new canvas and moves the slots across. Content, focus and form state are untouched because they never lived in the canvas.
