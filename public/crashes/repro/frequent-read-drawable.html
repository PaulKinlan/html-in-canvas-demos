A drawable 2D canvas made with willReadFrequently loses every 2D context on the page

A drawable canvas gets a 2D context with willReadFrequently: true. In one paint event the page calls drawElementImage() once and getImageData() for one pixel, and then does nothing more. A second, plain 2D canvas with nothing to do with the first is on the page to show what else is lost. Button B is the same without the option. Reload the page between the two: after A the losses go on for as long as the page is open, so a B pressed after A shows losses that are not its own. readback-matrix.html runs twelve cases in a page load each and shows that no read is needed.

Expected: no contextlost event.
Seen: Chrome 159 on Android 10, with A: contextlost on both canvases within 25 ms of the draw, then again about every 510 ms. With B on a fresh load: no loss. Headless Chromium 157 with software rendering: no loss.
