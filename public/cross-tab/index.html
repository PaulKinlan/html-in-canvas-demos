    How it travels

    1. Introductions. A popup gets a port directly: popup.postMessage({…}, '*', [port2]). An unrelated tab has no window reference, so both tabs connect to a SharedWorker that creates a MessageChannel and hands one end to each. After that they talk port to port.
    2. Frames. On every paint event the publisher draws the slotted elements, then cuts each element's region out with createImageBitmap(canvas, …) and transfers it. The element's client rect gives the region, because drawElementImage() moved its geometry to where it was drawn.
    3. Input. The viewer sends element-local pointer coordinates and keys. The publisher maps them with elementFromPoint(), focuses, clicks, and edits inputs with setRangeText().

    Takeaways

    • The snapshot can't follow the DOM to another tab. ElementImage is transferable, so postMessage to a popup succeeds, but the popup can't draw it: an ElementImage can only be drawn into the canvas it was captured from (or that canvas's OffscreenCanvas).
    • BroadcastChannel can't carry it at all. ElementImage is transferable but not serializable, so structuredClone and BroadcastChannel throw DataCloneError.
    • Pixels can. Because HTML-in-canvas strips sensitive content when painting, the canvas isn't tainted and an ImageBitmap of the drawn DOM can go anywhere: MessagePort, BroadcastChannel, popups.
    • So cross-tab reprojection is "remote framebuffer + input forwarding". It's live and interactive, but text in the viewer isn't selectable or accessible; the semantics stay in the source tab.
    • The source tab has to be rendering. The paint event runs in the rendering loop, so a hidden or backgrounded source tab stops sending frames. Side-by-side windows (or a popup) work best.
