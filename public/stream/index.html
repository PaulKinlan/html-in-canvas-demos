Streamed HTML drawn as it arrives

Markup is written into an element in small chunks with streamAppendHTML(). The element is a child of a canvas, and each chunk raises the canvas's paint event. A fragment shader draws every new block through an effect and makes the block that is being written glow. The text is real DOM the whole time: select it, scroll it, press the button when it arrives.

Show the code stream, track blocks, draw
  1. The element that receives the stream is a child of the canvas.
  2. Write chunks into it. streamAppendHTML() returns a WritableStream. Browsers without it get the same chunks through document.write() on a second document.
  3. Record when each block appeared and when it last changed. A MutationObserver maps every change to its top-level block.
  4. On paint, upload the element as a texture and draw it. The rectangles and ages of the blocks go to the shader as uniforms.
  5. The fragment shader. One pass. Each effect is a mask computed from a block's age.
  6. The upload. texElementSubImage2D() into a texture of exactly the element's picture size.
  7. Losing the WebGL context. The page shows the document as plain HTML until the context comes back.

How it works

The document is one drawable child of the canvas. A writer from streamAppendHTML() receives the chunks. A MutationObserver records when each top-level block appeared and last changed. On every paint event the element is uploaded as one texture with texElementSubImage2D() and drawn on one quad; the fragment shader gets the rectangles and ages of the newest blocks as uniforms and applies the effect inside them. The quad covers the element's layout box, so updateElementGeometry() gets an identity matrix.

Findings

  • streamAppendHTML() raises one paint event per chunk with no call to requestPaint() (Chromium 157). The page counts the events under the stage.
  • The paint event does not say which block is new: changedElements lists drawable children of the canvas, and the whole document is one child. A MutationObserver supplies the per-block timing.
  • The document scrolls inside its own box while it is drawn through the shader, and it keeps to the bottom while text arrives. Block rectangles are measured every frame, so the effect stays on its block during a scroll.
  • Chromium 153 has no streamAppendHTML(). Writing the chunks with document.write() into a second document, after moving that document's container into the canvas child, gives the same result there.
  • Not verified here: the on-device model. The test browser reports the Prompt API as downloadable and cannot download it, so the model button has only been run against a stub.
