Use it

<script type="module" src="/lib/dom-rewind.js"></script>

<dom-rewind seconds="30" trails="6" style="height: 400px">
  <div data-x="20" data-y="20">…any HTML…</div>
</dom-rewind>

<script>
  const rw = document.querySelector('dom-rewind');
  rw.place(rw.children[0], { x: 120, y: 40, rotate: 0.1 });
  rw.seek(2.5);          // 2.5 s ago
  rw.restore();          // or rw.live()
  rw.oncapture = () => appState;        // optional: ride along with each frame
  rw.onrestore = (state) => { appState = state; };
</script>

What we learned

  • An ElementImage is a cheap frame. It keeps drawing the element as it was when captured, after the element has changed or even left the document, and hundreds can be held at once. The paint event's changedElements says exactly which children need a new one, so idle and merely moving elements share a snapshot across frames.
  • Old frames are pictures, not DOM. A snapshot has one method, close(). You cannot select its text, query it or lay it out again. So "going back" for real means keeping state next to each frame (values, checked, open, scroll, app data) and putting it back, which is what restore() does.
  • Drawing a snapshot moves the live element's hit box to where the snapshot was drawn. Trails draw the live elements last, and the past is made click-proof while you look at it.
  • History survives a resize. Snapshots captured before the canvas changed size still draw, and their default size is recomputed for the new canvas grid.
  • Snapshots scale like vectors. An old frame drawn at four times its size is re-rasterised from the recorded paint commands, so text stays sharp where a bitmap of the same frame goes soft.
  • Alpha, filters and blend modes all apply to drawElementImage, which is all trails need.
