Which 2D operation loses the canvas

Pages on this site that use only 2D canvases have lost their canvases, or the whole tab, on a phone (Chrome 159 on Android), and not in the test browser. Each row below does one thing that those pages have in common, alone, for about four seconds. Press "Run every trial" on the device that has the problem. If the tab dies, open this page again: the row that was running says so.

Nothing has run. The small canvas beside the buttons stays on the page through every trial: a trial that loses it has lost every accelerated canvas.

Live checks

Each trial is a check that waits for a press. A result is stored in this browser before the trial starts and after it ends, and sent to the site's report log, so a result survives a tab that dies.

How it works

  • A trial builds its canvases in the box above, runs for about four seconds, removes them and gives them to window.__gfx.retire(). The next trial starts one second later.
  • Before a trial starts, its row is written to localStorage as "running". When it ends the row is written again with the outcome. A page load that finds a row still "running" reports that the tab stopped during that trial.
  • Every canvas of a trial has a contextlost listener. So has one plain 2D canvas that is made at load and never removed. Accelerated 2D canvases share one connection to the GPU process, so a trial that loses that connection loses this canvas too.
  • Each start and each outcome is also sent with window.__gfx.report('trial', …) to /api/reports, with the user agent. npm run reports -- --type trial --list prints them.
  • While trials run the page sets window.__checkState to "running", so the guard counts their readbacks as asked for.

Findings

From Chromium 157 with software rendering, 2026-11-21. The rows above say what your browser does.

  • Measured: no trial loses a canvas in the test browser. All seventeen end with "no loss". That browser keeps canvases in ordinary memory, so this says the trials run, not that they are safe.
  • Not verified: every trial on a phone. The page exists to be run there. A loss in one row and not in the base case names the operation.
  • Limit: one operation at a time. A loss that needs two of these together, or more than four seconds, is not found by this page.
