canvas → slot, nothing else

The markup you would want to write: a <slot> inside a normal <canvas>, and normal elements elsewhere with a matching slot attribute. No template, no shadow root, no custom element.

Native: just the markup With one script: light-slots.js

This paragraph sits between the canvas and the slotted elements, in the normal document flow.

<canvas id="stage" content="drawable">

<section slot="first">…</section>
<section slot="second">…</section>

<script type="module">
  const stage = document.getElementById('stage');
  const ctx = stage.getContext('2d');

  stage.onpaint = () => {
    ctx.reset();
    let x = 20;
    for (const slot of stage.querySelectorAll('slot'))
      for (const el of slot.assignedElements()) {
        ctx.drawElementImage(el, x, 20);
        x += el.offsetWidth + 20;
      }
  };
</script>

What is going on

  • Natively, nothing is projected. A <slot> only does something inside a shadow tree, and then only for children of that tree's host. In a plain document slot.assignedElements() is empty, the sections render in normal flow below, and drawing them throws because they are not inside the canvas. That is why the other demo wraps the canvas in a <template shadowrootmode>.
  • One script makes this exact markup work. light-slots.js attaches a shadow root to the canvas's parent, moves the canvas into it (same element, your references stay valid), and assigns matching siblings to the canvas's slots. Everything else keeps its place.
  • The cost of the workaround: slotted elements have to share a parent with the canvas (or opt in to being moved with slots="document"), and document CSS reaches the canvas only because the script copies stylesheet rules into the shadow root.
  • The platform gap: if <canvas content="drawable"> treated its own <slot> children as real slots for elements in the same tree, this page would work with no script at all. Worth proposing on the WICG repo.
