Shader CSS

Add fx="ripple" to an element and it is drawn through a fragment shader. Nothing else changes: the button still clicks, the field still takes typing, the text is still selectable and in the accessibility tree. CSS custom properties are the shader's uniforms, so transitions and :hover animate it.

How it works

  • The attribute wraps the element. A MutationObserver finds [fx] and wraps the element in <fx-surface>, which slots it into a canvas the same size. Remove the attribute and it is unwrapped.
  • Direct backend: the canvas is WebGL and texElementSubImage2D() uploads the DOM straight into a texture, only when the DOM repaints. One quad, one fragment shader.
  • Shared backend: browsers allow about 16 WebGL contexts per page, so after the first eight surfaces the rest use a 2D canvas: drawElementImage(), copy into one shared WebGL context, shade, draw back. Unlimited surfaces for two extra copies per frame.
  • CSS is the control surface. --fx-progress and --fx-amount are registered as numbers, so they transition and animate. The surface samples the computed value each frame and redraws only when a uniform changed.
  • Interaction stays put. The element's hit-test geometry is its layout box. Displacement is visual only, like a CSS filter. With reduced motion on, time-driven effects hold still.
