How it works

The arena puts N moving buttons and one moving text input through four paths: plain DOM moved with CSS transform: translate3d(), a 2D drawable canvas calling drawElementImage(el, x, y, w, h), and one WebGL 2 ElementGL context calling updateElementGeometry() either alone or paired with el.toggleAttribute('data-hit').

In Chromium 157 and Canary 160, moving a drawable element's geometry with updateElementGeometry() after the browser has already hit-tested it can leave Chromium's hit-test cache pointing at the old rectangle until a DOM attribute or style change invalidates it. The third mode leaves that toggle off on purpose so you can see and measure stale misses and ghost hits. The fourth mode turns the toggle on so you can measure what invalidating 1 to 200 elements every frame costs in JavaScript time, style recalculation and Long Animation Frames.

Every tap, drag and keypress inside the arena is observed with PerformanceObserver({ type: 'event', durationThreshold: 0 }). Each entry is split into input delay (processingStart - startTime), processing duration (processingEnd - processingStart) and presentation delay (startTime + duration - processingEnd). Chromium rounds Event Timing duration to 8 ms steps for privacy, so presentation delay is clamped at zero when rounding pulls the total slightly under processingEnd. On every pointer down, the page compares your pointer coordinates against the drawn control rectangles and document.elementsFromPoint() to count exact hits, stale misses and ghost hits at old positions.

Findings

  • Not verified yet on real hardware or headless Chromium: this page was built on 2026-11-26 and its live INP and 1 to 200 control sweep numbers haven't been collected from desktop Chrome or my Android phone yet. Open the page in Chrome with #canvas-draw-element enabled, tap and type across all four modes, run the sweep, and use Copy Markdown to record the results in findings/perf-inp.md.
  • Why the cache-bust mode is tested separately: earlier experiments in this repository (recorded in /crashes/ and /friction/ on Chromium 157 and Canary 160) hit a stale hit-test cache whenever a drawn element moved without an attribute toggle. Toggling an attribute on every moving control clears that cache, which may also trigger per-frame style invalidation and extra paint work as control counts rise toward 200.
  • Coordinate scaling at high device pixel ratios: updateElementGeometry() takes geometryUnit() from /lib/surface.js so the WebGL hit boxes line up on a 2.625 DPR Android screen as well as at 1x desktop scale.
  • Open items that need a real phone: touch drag responsiveness, software keyboard and IME typing latency inside the moving canvas input, and whether 200 attribute toggles per frame push mobile frame times past 50 ms LoAFs.
