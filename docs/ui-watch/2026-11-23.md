## What stood out

- Someone posted this site to Hacker News today as "HTML-in-Canvas Experiments" (2 points when I looked). It is in the [story search](https://hn.algolia.com/api/v1/search_by_date?query=%22html-in-canvas%22&tags=story).
- Chrome 157 made the API stable. The [announcement](https://developer.chrome.com/blog/html-in-canvas) is dated 26 October 2026 and reached Hacker News on 17 November.
- Three demos by Baked Design Studio went up on html-in-canvas.dev on 29 October. They are the most finished work by anyone else that I found, and each does something this site has no page for: text that re-flows round a moving shape every frame, snow that settles on live type, and a form under water.
- [CanvasUI](https://canvasui.dev/) now lists 38 components, 14 of them marked new. It is the first component library built on the API, and its components are page effects (cloth, heat haze, shatter, peel). None of them is a form control. That gap is what this site covers.
- [VFX-JS Transitions](https://amagi.dev/vfx-js-transitions/) (10 November) wraps an element in a canvas only while a transition plays, and leaves plain DOM the rest of the time. I think that is a good answer to the cost of keeping a canvas alive, and this site hasn't measured it.
- The interface work that designers shared this month keeps returning to four things: liquid and metaball shapes (seven finds), glass with refraction (three), paper that tears or crumples (three), and controls that wear or deform when used (five). The site has glass and tearing. It has nothing with metaballs, crumpling or wear.
- Open UI spent both November calls on `<rangegroup>` and the filterable `<select>`. Both are controls that a canvas page here could draw today from the Chromium prototypes.

### Liquid shapes (seven finds, one technique)

Liquid Arrow Button, Liquid UI Components, Liquid Popover, Reshaping Dock, the [Metaball Loader](https://memorabl.es/work/metaball-loader) by Sasha Birukoff, the [Gooey Sticky Menu](https://tympanus.net/Demos/GooeyStickyMenu/) by Manoela Ilic on Codrops (13 November) and the [Liquid Glass Bubble Components](https://memorabl.es/work/liquid-glass-bubble-components) by Cristian Javier all join and split shapes as if they were drops.

The CSS way is a blur followed by a hard contrast on a wrapper. It works on flat shapes and ruins any text inside, so each of these demos puts its labels in a second layer and keeps the two in step by hand.

A canvas removes the second layer. Draw the elements into an offscreen field, blur it, cut it at a threshold to get the joined outline, then draw the same elements again, sharp, inside that outline. The labels, focus rings and hit boxes are the real ones. A `ctx.filter` blur works on `drawElementImage()` (`findings/form-state.md`), so the 2D route may be enough and a shader is the second route.

The site has nothing like this, and it answers a question the API is well placed to answer. I'd build it as one page with a button, a dock and a menu.

From [open-ui.org](https://open-ui.org/) and the minutes of the Open UI calls. A canvas page can draw a proposed element once Chromium has a prototype behind `chrome://flags/#enable-experimental-web-platform-features`, and such a page tells the people writing the proposal something they can't get elsewhere: whether the element's parts paint and hit-test when drawn somewhere else.

## What I'd build next

In order. Each is one page and one pull request. All use native elements underneath.

1. **Liquid shapes** (`/liquid-shapes/`): a button whose arrow pinches off, a dock that bulges round the hovered link and a menu that pours from its button, all from one blurred field cut at a threshold with the real elements drawn sharp inside. Credit: Kopp, Matt Ölschlegel, Sasha Birukoff, Manoela Ilic. Seven finds use the technique and the site has none.
2. **Controls that wear** (`/worn-controls/`): a `<button>` that chips and collects fingerprints with each click, kept in a second canvas. 2D only, so it runs on every phone. Credit: Florian Kiem, Adam Kowalski.
3. **Sliders that deform** (`/elastic-range/`): one `<input type="range">` drawn three ways. A track that bends like a string, bars that dip round the thumb and ticks under a lens. Credit: Gabriel Obholz, Shiv, Nitish Khagwal. If the test browser has `<rangegroup>`, a fourth with two thumbs.
4. **Genie minimise** (`/genie/`): a `<dialog>` poured into a dock in strips, and back out. Credit: Raphael Salaja. It tests the hit box after many source-rectangle draws.
5. **Theme switch through a shader** (`/theme-sweep/`): a switch that changes `color-scheme` while a shader mixes the old picture of the page with the new one. Credit: saint.
6. **Crumpled receipt** (`/crumple/`): a receipt that crumples, can be thrown, and smooths out with creases. Credit: Lorenzo Cabra, Matt Ölschlegel.
7. **Text that makes room** (`/text-wake/`): a paragraph that re-flows round a shape you drag, drawn each frame. Credit: Baked Design Studio's Margin Dragon. It measures what layout on every frame costs on a phone.
8. **Cloth** (`/cloth/`): an article hung on a cloth mesh in a native scroller, with a clear statement of when its links can be hit. Credit: Jesper Landberg, Thomas Richter-Trummer, CanvasUI.
9. **Punch-out picker**: a sixth layout for `lib/select-picker.js`. Credit: Fabio Azevedo. It goes in the customisable select thread.
10. **Canvas only while it moves**: a measurement page. The same transition with a canvas that is always there and with one that exists only during the transition, as VFX-JS does. It reports memory from `window.__gfx.memory()` and time to first frame.
